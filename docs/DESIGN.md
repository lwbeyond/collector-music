# 看板设计规范

适用范围：`collector_music/web` 的概览、收听历史、数据分析、榜单、收藏、采集状态及其弹窗。新组件和调整沿用本规范。

用户原则：

> Avoid unnecessary secondary labels and descriptions. Let the layout do the explaining.

先用位置、对齐、间距和字重说明关系。增加一行文字前，确认它是否提供了当前布局、标题或控件尚未表达的信息。

## 信息取舍

- 每个区块只保留一个主标题。删除重复英文、编号眉题、标题下的功能介绍及页尾宣传语；操作控件使用清楚的动词。
- 控件已显示的来源、时间、排序和搜索词，不再逐项复述。搜索框占位提示说明可搜字段；无匹配结果时才提供调整建议。
- 字段名称、数值、单位构成一组。相同单位或快照日期放在共同表头或列表说明中，不在每行重复。数值右对齐，使用等宽数字。
- 统计概览和指标矩阵使用标签与数值；不为每项补一段常识解释。峰值日期、凌晨时段等能改变数值含义的信息可就近保留。不要再用默认展开的摘要逐句复述矩阵。
- 每个数据区保留一条简短、就近的口径说明。完整算法、来源差异与限制放入可展开的“统计口径”；正常状态下不叠加多段提示。
- 状态文案随状态出现。正常读取完成后不保留加载说明；无数据、读取失败、旧快照和结果受限时直接说明原因与可执行动作。

以下信息会改变用户对数据的判断，不能为简洁而隐藏：采集失败后使用旧快照、数量未知、红心详情缺失、历史列表载入上限、混合来源可能重复、双源重合候选、未纳入分析的无效时间。空白日期不能写成零播放；曲长不能写成实际收听时长。

## 布局与视觉

保留深色底、低饱和香槟金和衬线主标题。页面以单一、不透明的深色平面承载内容；统计、列表、来源和分析图表通过分栏、细线及留白组织。

| 项目 | 约束 |
| --- | --- |
| 背景 | `--bg` 为页面与普通区块共用底色；不使用背景渐变、玻璃模糊或全页光晕。 |
| 浮层 | 下拉菜单、tooltip、dialog 使用 `--surface`；只比页面略亮，最多一层中性阴影。 |
| 文字 | `--ink` 为主要内容，`--muted` 为次要信息；正文与背景对比至少 4.5:1。不能靠低到难读的透明度减少存在感。 |
| 强调色 | `--accent` 为低饱和香槟金 `#c5ab87`；只用于主要动作、当前选中项、图表数据和少量链接反馈。不得铺满每个标签。 |
| 分隔 | `--line` 为 1px 中性细线；普通区域使用横线或列间线，不同时包围外框和每个子项。 |
| 圆角 | 输入框与按钮 4px；普通内容区域不使用圆角卡片；浮层 4–8px。圆形只用于确有形状含义的元素。 |
| 阴影 | 常态内容、按钮、统计、来源、歌单均无阴影；浮层允许单层如 `0 8px 24px rgba(0,0,0,.24)`，不叠加金色光晕或 inset 高光。 |
| 字体 | 沿用本机字体栈。衬线用于主标题；正文、控件和数据使用无衬线；不加载外部字体。 |
| 字号 | 页面主标题桌面 46px、窄屏 36px，区块标题 24–28px，正文与控件 13–16px，必要辅助信息 12–13px；图表刻度可用 11px，不随整图压缩成微小字。 |
| 间距 | 以 4px 为基准：同组 4–8px、相邻控件 8–12px、组间 16–24px、区块 32–48px。优先调整间距来区分层级。 |
| 动效 | 普通交互仅改变文字、底色、边线，120–180ms；不使用 hover 上浮、横移、持续旋转或装饰性闪烁。加载反馈除外，并支持减少动态效果。 |

具体颜色统一由 `style.css` 的 `:root` 管理。新增组件复用语义 token；不要以文件末尾连续覆盖的方式保留已废弃的玻璃、高光或卡片样式。

## 各区落实方式

| 区域 | 保留 | 删除或合并 |
| --- | --- | --- |
| 概览 | 标题、最近发布时间、主要入口、最近设备曲目、四项独立统计 | 英文副品牌、口号式介绍、装饰唱片、发光状态点、每项统计的独立底板 |
| 收听历史 | 搜索与筛选、结果数量、来源边界、表格和分页 | 复述搜索功能的段落、正常状态下重复全部筛选值的摘要 |
| 分析 | 来源与时间控件、视图标签、图表单位、日期范围和必要口径 | emoji 图标、重复视图标题、默认展示的操作教学、多次重复来源声明 |
| 指标 | 标签、数值、必要日期/时段、可展开的算法 | 每格通用解释、默认展开且重复数值的文字摘要 |
| 榜单与收藏 | 曲名、艺人、序号/数量、必要类型、快照状态 | 伪封面装饰、每行重复“平台次数”、每张歌单重复同一快照日期 |
| 采集状态 | 来源名称、当前状态、记录数、最近接收/采集时间 | 各来源独立浮起的卡片、反复解释本地保存和同步方式的文案 |

榜单、收藏和明细默认使用行结构。窄屏允许一行折成两至三行，仍靠对齐和分隔线分组，不为每条记录重建圆角卡片。

## 交互与可访问性

- 减少可见标签不等于删除字段名称。表单保留 `<label>` 或准确的可访问名称；自定义下拉保留“字段名：当前值”的可访问名称。无法从选项清楚判断用途时，应保留可见字段标签。
- 当前标签页、选中来源、禁用动作和键盘焦点均有清晰反馈，不能只靠颜色区分。保留 `aria-selected`、`aria-pressed`、状态通知和键盘行为。
- 主要点击目标及表单触发器至少 44px 高；图表的小单元允许专用键盘导航，并提供可访问数据说明。
- 曲名、艺人、专辑和错误内容允许换行。长字符串不能撑宽页面；不通过整页横向裁切掩盖溢出。
- 外链行为、原有搜索/分页/筛选、刷新保留上下文、数据边界与安全约束继续遵循 [看板说明](DASHBOARD.md)。

## 回归清单

每次设计变更按以下条目检查，并在验收记录中写明实际视口、数据状态及未验证范围。本规范本身不代表检查已通过。

- [ ] 1440px 桌面和 390px、320px 窄屏逐区查看；无页面横向溢出，标题与控件不拥挤。
- [ ] 同屏没有重复英文眉题、功能解释、筛选复述或重复摘要；保留的辅助文字都提供新增信息。
- [ ] 普通统计、来源、列表和图表无阴影、玻璃模糊、渐变底、胶囊堆叠、hover 位移；浮层与焦点仍清晰。
- [ ] 默认、长曲名、无匹配、首次无数据、旧快照、请求失败和记录截断状态均可辨识；必要限制仍在相关数据附近。
- [ ] 桌面与窄屏完成搜索、来源/日期切换、排序、分页、收藏切换、四个分析视图、艺人明细、导出及刷新。
- [ ] 仅用键盘完成导航、筛选、图表数据查看、弹窗关闭；隐藏的原生 select 不额外占用焦点。
- [ ] 修改后运行对应的 `test:ui` 与 `test:analytics` 浏览器回归；记录结果，不以静态检查替代实际页面观察。
